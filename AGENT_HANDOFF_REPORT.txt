1. PROJECT GOAL
---------------
The goal of this project is to create a local-first AI College application that can run entirely on a local machine without requiring cloud AI services. The application includes:
- a FastAPI backend,
- a React/TypeScript frontend,
- a local AI assistant powered by Ollama,
- a SQLite-backed data layer,
- and a simple local dashboard for college-related demo data.

The intended model is: local user machine or lab machine -> React frontend -> FastAPI backend -> SQLite -> Ollama runtime -> local model.

2. WHAT THE PROJECT IS
----------------------
The repository is an AI College system. It provides a working local environment that includes:
- a dashboard UI,
- room/device/event models and APIs,
- AI status and chat endpoints,
- and an Ollama provider abstraction for local AI.

The app is designed to be local-first and private. The AI assistant should use a local Ollama model rather than cloud APIs.

6. WHAT THE INSTALLER DOES IN DETAIL
------------------------------------
The main installer script performs a full setup workflow for a new machine.

6.1 It checks the repository layout
It expects the presence of:
- backend/
- frontend/

If those are missing, it exits with an error.

6.2 It installs missing system prerequisites
The script checks for these tools:
- python3
- python3-venv
- node
- npm
- curl

If one or more are missing, it can install them automatically depending on the operating system.

Supported OS families:
- Debian/Ubuntu: uses apt-get
- Fedora/RHEL/CentOS/Rocky: uses dnf or yum
- Arch/Manjaro: uses pacman

If the user runs with -y or --yes, it will auto-install these prerequisites without prompting. Without -y, it may ask the user first.

6.3 It creates .env from .env.example if missing
If .env does not exist, the script creates one from .env.example. This is important because the application expects environment variables at runtime.

6.4 It creates a Python virtual environment
The script creates and uses:
- backend/.venv

This is the Python environment for the backend dependencies.

6.5 It installs backend Python dependencies
It installs the packages listed in:
- backend/requirements.txt

The dependency list includes FastAPI, Uvicorn, SQLAlchemy, Pydantic settings, Pytest, and httpx.

6.6 It installs frontend Node dependencies
It runs npm install or npm ci in the frontend folder using:
- frontend/package.json

6.7 It installs Ollama if missing
If the ollama command is not available, the script can install Ollama using the official install script from ollama.com.

6.8 It pulls the configured AI model
The script reads the Ollama model from .env or .env.example. If no model is specified, it defaults to:
- qwen2.5:1.5b

It then checks whether the model already exists locally. If it does not, it runs:
- ollama pull <model>

6.9 It optionally starts Ollama
If the --serve flag is supplied, the installer starts:
- ollama serve

and writes the output to:
- ollama-serve.log

10. RUNNING THE APPLICATION AFTER INSTALLATION
---------------------------------------------
Once the installer finishes, the intended workflow is:

10.1 Start the backend
Open a terminal in the repository root and run:
- source backend/.venv/bin/activate
- cd backend
- uvicorn app.main:app --reload --port 8000

10.2 Start the frontend
Open another terminal in the repository root and run:
- cd frontend
- npm run dev

10.3 Access the app
The frontend should be available at:
- http://localhost:5173

The backend API docs should be available at:
- http://localhost:8000/docs

12. KNOWN CAVEATS AND ASSUMPTIONS
--------------------------------
The next agent should keep the following in mind:
- This project is designed to be local-only.
- It requires internet access for installing packages and pulling the Ollama model.
- Ollama installation may require sudo/admin privileges.
- The default model may take time to download depending on network and hardware.
- The app uses SQLite as the default database, which is suitable for development/demo but not for production scale.
- The setup script assumes that the repository has already been cloned and that the user is running it from the repository root.
