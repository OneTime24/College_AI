1. PROJECT IDENTITY AND PURPOSE
------------------------------
The repository is an "AI College" project. It is a local-first college/infrastructure management application with an AI assistant layer. The system is intended to run locally on a laptop or lab machine, with no dependency on cloud AI APIs.

The project combines:
- a backend API for college-related data and AI features,
- a frontend dashboard for viewing and interacting with that data,
- a local AI assistant powered by Ollama,
- and SQLite-based local storage for lightweight deployment.

The high-level design philosophy is:
- keep the system private and local,
- avoid cloud dependency where possible,
- make the app easy to run on a developer machine or small local lab machine,
- and make setup as automated as possible.

2. WHAT THE SYSTEM IS TRYING TO ACHIEVE
----------------------------------------
The project aims to provide a practical local system that can:
- serve a dashboard UI,
- expose REST API endpoints for rooms, devices, events, health, and AI status,
- let a user interact with a local AI assistant,
- and use an Ollama-hosted model to generate replies locally.

The expected user workflow is:
1. Clone the repo on a machine.
2. Run one installer command.
3. The system installs prerequisites and app dependencies automatically.
4. The system creates the required environment configuration.
5. The system pulls the required local model.
6. The user starts the backend and frontend.
7. The AI assistant is ready to use.

This is the entire reason the setup scripts were created.

4. CORE APPLICATION COMPONENTS
------------------------------
4.1 Backend
The backend is an API server built around FastAPI. It includes:
- health endpoints,
- system status endpoints,
- AI endpoints,
- room/device/event API handlers,
- database initialization logic,
- seed/demo data generation,
- service-layer orchestration,
- configuration loading,
- and AI provider integration.

The backend is structured into:
- app/api for endpoints,
- app/services for business logic,
- app/models for database models,
- app/schemas for request/response validation,
- app/config.py for runtime settings,
- app/database.py for database creation and session handling,
- and app/seed.py for demo data bootstrapping.

4.2 Frontend
The frontend is a React + TypeScript web application that provides:
- a dashboard view,
- room and device pages,
- event/activity views,
- an AI Assistant page,
- API communication logic,
- and a local UI experience that talks to the backend API.

The main frontend code is in the frontend/src directory, and the package dependencies are defined in frontend/package.json.

4.3 AI subsystem
The AI subsystem is built to use an LLM provider abstraction. The current implementation targets Ollama. In practice, this means:
- the backend asks an AI provider to generate a response,
- the provider talks to the local Ollama runtime,
- and the model runs locally rather than through a cloud API.

This is one of the project’s central design goals.

7. WHAT THE INSTALLER SCRIPT DOES IN FULL DETAIL
-----------------------------------------------
The main installer script is designed to be the central entrypoint for new-machine setup.

7.1 It validates repository structure
It checks for the presence of the backend and frontend folders. If those are missing, setup cannot proceed.

7.2 It ensures required tools are present
The script verifies that these tools are available:
- python3
- python3-venv
- node
- npm
- curl

If they are missing, it tries to install them using the native package manager for the OS.

7.3 It installs prerequisites automatically when possible
The script supports:
- Debian/Ubuntu with apt-get,
- Fedora/RHEL/CentOS/Rocky with dnf or yum,
- Arch/Manjaro with pacman.

This makes the system more resilient and better suited for a fresh machine.

7.4 It creates environment configuration
The script creates .env from .env.example if .env does not already exist. This is essential because the app requires environment variables to run.

7.5 It creates the Python virtual environment
The backend virtual environment is created at:
- backend/.venv

This isolates the Python packages from system Python and makes the backend install self-contained.

7.6 It installs backend dependencies
The script installs Python packages from:
- backend/requirements.txt

These dependencies include FastAPI, Uvicorn, SQLAlchemy, pydantic-settings, pytest, and httpx.

7.7 It installs frontend dependencies
The script installs frontend packages using npm in the frontend directory.

7.8 It installs Ollama if missing
If the ollama binary is not available, the installer can fetch and install Ollama using the official install script.

7.9 It pulls the configured local model
The script reads the configured Ollama model from .env or .env.example. If no model is specified, it defaults to:
- qwen2.5:1.5b

It checks if the model is already present locally. If not, it pulls it with ollama pull.

7.10 It optionally starts Ollama service
Using the --serve flag, the script can start ollama serve in the background and write logs to ollama-serve.log.

8. HOW THE USER IS EXPECTED TO RUN IT
-------------------------------------
The intended fresh-machine workflow is:

1. Clone the repository.
2. Open the repository folder.
3. Run:
   - ./install.sh

Or equivalently:
   - ./setup_one_click.sh

For a more automated experience:
   - ./install.sh -y --serve

This is the “single-command install” experience the repository was missing before this session.

9. WHAT SHOULD HAPPEN AFTER INSTALLATION
---------------------------------------
Once the installer completes successfully, the next expected step is to start the backend and frontend.

9.1 Backend start
In one terminal:
- source backend/.venv/bin/activate
- cd backend
- uvicorn app.main:app --reload --port 8000

9.2 Frontend start
In another terminal:
- cd frontend
- npm run dev

9.3 Expected access points
- frontend: http://localhost:5173
- backend API docs: http://localhost:8000/docs

If Ollama was installed and the model was pulled successfully, the AI assistant should be able to use the local model.
